## CRITICAL — Security (the deferred RLS work is now urgent)

1. **Publishable key = full DB credential.** With RLS off everywhere, anyone with the URL + key from view-source can read/write/delete every table from curl. The repo is **public on GitHub** (required for free Pages), so the key is indexed and discoverable — the exposure is broader than the spec's "leaked photo URL" framing (docs/specs line 63).
2. **Plaintext passwords in a world-readable `users` table.** Login is `sb.from('users').select('*').eq('email',..).eq('password',..)` (line 372); user-add (2192) and password-reset (2204) write plaintext. Anyone can `select * from users` and get every employee's email + password + role. Treat all current passwords as compromised after migration.
3. **Login/auth is entirely client-side.** No server-issued session; `onLogin(data)` receives the full row including password. Session = JSON user object in `localStorage['lincoln_tms_user']` (2526–2541) — forgeable; setting `role:"admin"` in devtools grants the full admin UI (gates at 2210, 2382, 2551).
4. **Public photo bucket, predictable paths, listable** (287–358). Anyone can scrape, overwrite, or delete every photo; permanent `public_url`s are stored in the world-readable `photos` table.
5. **All destructive ops (delete WO/customer/job/part/photo, void, user deactivate) are bare client calls** gated only by `confirm()`.

**Remediation order:** (1) Migrate to Supabase Auth (`signInWithPassword`), drop table-based login; (2) enable RLS on all 12 tables + storage with authenticated policies — `users`/`audit_log` admin-only, `audit_log` insert-only; (3) make `tms-photos` private + signed URLs, stop persisting `public_url`; (4) force password reset for everyone; (5) consider moving hosting to Cloudflare Pages (`wrangler`, already used for Shingle) so the GitHub repo can go private.

XSS note: surface is small and well-handled — React auto-escaping everywhere, `esc()` on the DOT print path. Only hardening note: `esc()` doesn't escape quotes, so never move an `esc()`-ed value into an HTML attribute.

## HIGH — Correctness bugs

1. **Silent write failures + audit log lies.** Most mutations ignore `res.error` (kanban status 829, WO delete 836, job add/status/delete 996/1002/1009, mechanic assign 1367, labor 1386, notes 1399, part status 1045, reminders 867/2019/2026, appointments 1891, user mgmt 2192/2197/2204…). Supabase resolves with `{error}` — on flaky shop Wi-Fi the change is dropped, the UI looks fine, and `audit()` still logs success. Fix: a `must()` helper that alerts + throws on error at every write site; call `audit()` only after success.
2. **Labor/notes blur-save stale-compare desync** (1379–1405). After save, `jobsList` isn't refreshed; correcting a value back to its prior on-screen number is silently skipped — DB and invoice keep the wrong hours. Fix: refresh or patch `jobsList` after each save.
3. **Customer rename breaks all name-keyed links** (1743–1756). `work_orders.customer`, `reminders.customer_name`, `equipment.customer_name`, `appointments.company` store the name string; rename orphans them (contact card vanishes at 1297, badges reset at 1693). Fix: cascade-update denormalized names on rename, or block rename.

## MEDIUM — Correctness

4. **Revenue is computed from `work_orders.labor` (dollars), but the workflow records `jobs.labor` (hours)** — Dashboard 463, Reports 2286, Salaries 2266, Invoices 2322, Estimates 2341. Line 702 admits `w.labor` is unused. Invoices for completed work read $0 labor; Dashboard "Revenue" also counts waiting-list WOs. Decide the source of truth (hours × shop rate) and fix all five readers.
5. **"Today" computed in UTC** (458, 630, 1852, 1972) — reminders flip overdue ~6h early in Nebraska. Build local date string in one shared helper.
6. **`auto_days` recurring reminders are a silent no-op** (545, 589, 620, 636) — nothing computes `reminder_date` from it; such reminders never fire. Implement on-complete rescheduling or remove the field.
7. **Photo pipeline gaps** (296–330): DB insert after storage upload unchecked (silent photo loss); delete ignores errors (orphans); WO renumber detaches `photos.entity_id` (`work_order/<id>`, `dot_item <woId>__<key>`) — cascade comment at 794–795 misses photos/reminders/dot.
8. **No double-submit protection** on any create button except photos/login — double-tap on tablets duplicates jobs, customers, notes, appointments, users.
9. **Login UX:** network/RLS errors reported as "Incorrect email or password" (370–375); Enter key doesn't submit. Also **deactivated employees keep working sessions forever** — `users.active` only checked at login (2526–2541); re-check on app mount.

## HIGH — Mobile / Desktop UI

1. **Four independent `useViewport()` instances can disagree on tier** (236, 452, 1947, 2550) — hysteresis is path-dependent, so a modal can render in tablet mode while the shell is desktop. Root of remaining Samsung pain. Fix: single viewport store/context.
2. **Raw-width branches bypass hysteresis** — Modal `<700` (237), Dashboard `<600/<900` (482), Reminders `<900` (2050). Flicker still live at those boundaries. Branch on tier instead.
3. **CSS/JS breakpoint mismatch 1280–1319px:** JS holds "tablet" to 1320 (90) but touch-target CSS ends at 1279 (25) — touch tablets in that band lose all 44px sizing. Align, or drive CSS from a `data-tier` attribute.
4. **DOT print: dark headers vanish without "Background graphics"** (898–945). Add `print-color-adjust: exact` + black-text fallback — this is a federal inspection document.
5. **Seven tables clipped (not scrollable) on phones** — wrappers use `overflow:hidden`: Voided WOs (1102), Appointments (1909), Users (2217), Salaries (2262), Invoices (2314), Estimates (2333), AuditLog (2428) + 6-col filter bar (2395) + WO list grid `240px 1fr` (1161). Copy the RemindersPage pattern (`overflow:auto` + `minWidth` + card view <900).

## MEDIUM — UI
- **Viewport lock** `maximum-scale=1, user-scalable=no` (line 5) blocks pinch-zoom — WCAG 1.4.4 failure, real cost in a shop. Likely root cause was sub-16px inputs (29 sets 15px → focus auto-zoom). Bump inputs to 16px, then relax the meta.
- **Full-sheet modal `100vh`** (239) — Save/Cancel hidden behind keyboard/URL bar. Use `100dvh` + safe-area bottom padding.
- **No scroll containment** on modal/lightbox/drawer (241, 351, 2492) — body scrolls behind overlays. Lock body overflow + `overscroll-behavior:contain`.
- **Sub-44px touch targets:** photo delete × is 20px and the blanket `min-height:40px` rule (33) distorts it to 20×40; kanban ✏️/🗑 (1133); reminder row actions (2109). Give icon buttons 40–44px minimums; exempt tiny overlays via class.
- **Hover-only affordances:** Quick-Add chips stick dark after tap (1324); `title=` tooltips are the only label for several actions — invisible on touch.
- **Login:** no `<form>`/Enter submit, no autocomplete attrs (368–392).
- **Wrong mobile keyboards:** zero `type="tel"`/`inputMode` — phone (1278, 1809), ZIP (1535), odometer (1558), MC/DOT (1280) all get QWERTY.
- **Labels not associated** — `Field` (256–263) lacks `htmlFor`/`id`.

## Performance / Architecture

1. **HIGH: babel-standalone compiles ~190KB of JSX in the browser on every load** (lines 7–10, 50) — ~3MB of compiler JS, seconds of parse on a Samsung tablet. Fix: ~20-line build script (`npx esbuild --loader=jsx`) emitting `dist/index.html` without the runtime compiler. Biggest perf lever in the project.
2. **HIGH: DOT tab fires ~44 photo queries on open** — `PhotoSection` self-fetches per instance (287; DOT 1586, customers 1798, jobs/parts 1409/1470). Fetch once at parent (`.like('entity_id', woId+'__%')` / `.in()`), pass down via optional `photos` prop.
3. **HIGH: full-table unfiltered selects, refetched on every mutation** — `loadWos` pulls all of `work_orders`+`jobs`+`parts`+`notes` (735–748) after every change; Dashboard (456), Reminders (1961), Reports (2284), Salaries (2255) download whole tables for counts/sums. Add limits/date floors; the audit log (2356–2376) is the pattern done right.
4. **MED: view/RPC candidates** — dashboard tiles, customer jobs-completed badge, report/salary sums, and a `work_orders_summary` view (sum jobs.labor, note counts, part rollups) that removes 3 of 4 full-table queries from the hottest path. Would also unlock a real period selector (hardcoded "Mar 2026", 2261).
5. **MED: full-size 1600px JPEGs in 56px tiles, no lazy loading** (343) — add `loading="lazy" decoding="async"`; consider second small thumb at capture (resize pipeline at 266 already exists).
6. **MED: supabase-js floats on `@2`** (10) — an upstream regression deploys itself. Pin exact version or vendor all 4 CDN libs into the repo.
7. **MED: `openJobs` awaits 5 queries serially** (850) — `Promise.all`, one-line fix, biggest perceived-latency win.
8. **Maintainability:** `WorkOrders` is a 975-line component with ~35 useState hooks (698–1673) — extract the details modal (1295–1653) first. Reminder CRUD duplicated 4× (586, 851, 1716, 2000). Don't split files until the next major feature (Invoices/Inventory).
9. **Dead code/stubs:** unreachable `notesModal`/`openNotes` (~35 lines, 840–846, 1655–1670); unused `responsive()` (117); no-op Invoice/Estimate Create buttons (2313, 2332) look broken — disable or remove; Salaries total hardcoded `—` (2272).
